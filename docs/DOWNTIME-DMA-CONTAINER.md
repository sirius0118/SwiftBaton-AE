## 实测收益边界

全局 DMA MR 目前没有证明停机收益。普通 MR 的210431（整轮失败，时间仅供诊断）源最终准备102.729 ms，其中导出73.893 ms；DMA的211058源最终准备147.781 ms，其中导出112.393 ms。DMA地址表传输在源/目标记录为9.832/16.026 ms，属于重叠的发送/接收时间，不能相加当作新增停机。单轮且带目标诊断，不能将差异全部归因于全局 MR，但足以说明仅去掉硬件注册不会自动消除原来的导出成本。下一步须分解 pin、DMA 映射、向量构造，并将可保真的准备提前至 PS。

目标 ARM 在211058用户层包围区间为219.379 ms；内核逐区域计时总和218.430 ms，414区域/1562715页，细分如下：

| 步骤 | 汇总 ms |
|---|---:|
| token ID 数组分配 | 0.750 |
| 从 PS 池绑定 token/cookie | 21.087 |
| 内核桥接、查找 token、设置 PTE | 137.380 |
| 释放创建者持有的 token 引用 | 59.221 |

计时在正式调用位置收集，无CPU模型估算。其中最后一项值得优先后移：PTE 已持有自己的 token 引用，只要后台释放任务独立持有 context/模块、与关闭/失败路径明确交接所有权，延迟释放创建者引用原则上仅推迟最终 drain/源释放，不应阻止目标服务恢复。尚未实现或声称已获得这59 ms收益；需要对关闭、丢弃、fork、ARM失败和在途RDMA退役验证后再做实际对照。它也不能单独将约528 ms压到50 ms。

## 页面计数失败保留

210431 普通 MR 的迁移命令均返回0，但AE严格验证发现5页差额，驱动按失败退出并清理，没有运行完最终数据/客户端性能验证，也没有放宽条件重算为通过。诊断定位到目标 pid1、地址`7fdd2e665000`、5页 region：completed=0，retired=5，drained=1，5页均为QUEUED_BG，没有传输错误。这与合法映射丢弃相容，仍不足以证明该次原因。

新增默认关闭的模块参数 `retirement_audit`，在每个区域首次发生未取页 token 最后引用释放时记录实际调用栈；另启用已有 `arm_timing`。两种开关先经 KASAN/RXE 全套回归验证，随后仅在211058诊断实验启用。该次未出现未取页退役事件、计数完整，因此210431的具体丢弃原因仍未证实。旧193046的48页差额同样保留为未解决问题。严格页面计数检查未改变，不能用新的成功轮次替代失败证据。
